STARTUP GUIDE
=============

Everything runs from /Users/juleswitold/Dev/WriteMap-Dev/TaibledFork/ — this is
the working directory for both local dev and the two Docker stacks (dev + prod).
All docker compose commands below must be run from that directory.


## Two Docker stacks

Both stacks run in parallel from the same directory, kept separate by project name:

  Stack       Project name    Compose files                              Env file    Ports
  ─────────── ─────────────── ──────────────────────────────────────── ─────────── ──────────────
  Dev         writemap-dev    docker-compose.yml + docker-compose.dev.yml   .env      API :3100, Web :8180
  Prod        writemap        docker-compose.yml + docker-compose.prod.yml  .env.prod API :3000, Web :8080

The --project-name flag is required. Without it Docker names containers after the
directory (taibledfork-*) and conflicts with whichever stack is already running.


## Rebuilding after a code change

Rebuild and restart just the API (most common):

  Dev:
    docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml up -d --build api

  Prod:
    docker compose --project-name writemap -f docker-compose.yml -f docker-compose.prod.yml up -d --build api

Rebuild everything (api + web):

  Dev:
    docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml up -d --build

  Prod:
    docker compose --project-name writemap -f docker-compose.yml -f docker-compose.prod.yml up -d --build

If Docker's layer cache is stale and not picking up your source changes, add --no-cache:

  docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml build --no-cache api
  docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml up -d api


## Checking logs

  docker logs writemap-dev-api-1 --tail 30 -f
  docker logs writemap-api-1     --tail 30 -f
  docker logs writemap-dev-web-1 --tail 30 -f
  docker logs writemap-web-1     --tail 30 -f


## Environment files

  .env       — dev stack values (apidevhideandseek / devhideandseek URLs)
  .env.prod  — prod stack values (apihideandseek / hideandseek URLs)

Both are gitignored. If .env.prod is missing, create it from .env and swap the URLs:
  sed -e 's|apidevhideandseek|apihideandseek|g' -e 's|devhideandseek|hideandseek|g' .env > .env.prod


## Local Vite dev (no Docker, fastest iteration)

Run these three things in order from TaibledFork/:

1. Postgres — already running via Docker (either stack's postgres will do):

     docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml up -d postgres

2. API — from TaibledFork/apps/api/:

     node --env-file=../../.env --watch --import tsx/esm src/index.ts

3. Web — from TaibledFork/:

     pnpm --filter web dev

   Web: http://localhost:4321    API: http://localhost:3000

HMR applies only to the Vite dev server. Changes do NOT hot-reload in the Docker
stacks — you must rebuild the container to see them.


## First time / after a fresh clone

Run once to create tables and seed initial data:

  cd apps/api
  DATABASE_URL=$(grep DATABASE_URL ../../.env | cut -d= -f2-) npx prisma migrate deploy
  DATABASE_URL=$(grep DATABASE_URL ../../.env | cut -d= -f2-) npx tsx prisma/seed.ts

Only needed again if you wipe the Docker volume (see below).


## IMPORTANT — do NOT run these unless you mean to wipe the database

  docker compose --project-name writemap-dev down -v   # wipes dev DB
  docker compose --project-name writemap down -v       # wipes prod DB

`down` without `-v` is safe — stops containers but keeps the volume and all data.

Volume names:
  writemap-dev_postgres_data   (dev)
  writemap_postgres_data       (prod)


## Verify the stacks are healthy

  curl https://apidevhideandseek.lucifersserver.com/health   # → {"ok":true}
  curl https://apihideandseek.lucifersserver.com/health      # → {"ok":true}
