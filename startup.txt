STARTUP GUIDE
=============

Two separate git clones, one per stack:

  Dev clone:  /Users/juleswitold/Dev/WriteMap-Dev/TaibledFork/
              devhideandseek.lucifersserver.com  /  apidevhideandseek.lucifersserver.com

  Prod clone: /Users/juleswitold/Dev/WriteMap/TaibledFork/
              hideandseek.lucifersserver.com  /  apihideandseek.lucifersserver.com

Each clone has its own .env with the URLs for that environment. Never run the prod
docker compose command from the dev clone or vice versa — they use different .env files
and would bake the wrong URLs into the containers.


## Rebuilding after a code change

Always cd into the correct clone first, then:

  Dev (from /Users/juleswitold/Dev/WriteMap-Dev/TaibledFork/):
    docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml up -d --build

  Prod (from /Users/juleswitold/Dev/WriteMap/TaibledFork/):
    docker compose --project-name writemap -f docker-compose.yml -f docker-compose.prod.yml up -d --build

To rebuild only the API (faster, skips rebuilding the web container):

  Dev:  docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml up -d --build api
  Prod: docker compose --project-name writemap -f docker-compose.yml -f docker-compose.prod.yml up -d --build api

The --project-name flag is required. Without it Docker names containers after the
directory (taibledfork-*) and conflicts with the other running stack.

If Docker's layer cache is stale and not picking up source changes, add --no-cache to
the build step:

  docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml build --no-cache api
  docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml up -d api


## Typical deploy workflow

1. Edit code and commit in the dev clone (WriteMap-Dev/TaibledFork).
2. Push to GitHub.
3. Test on devhideandseek.lucifersserver.com.
4. When happy, pull into the prod clone and rebuild:
     cd /Users/juleswitold/Dev/WriteMap/TaibledFork
     git pull
     docker compose --project-name writemap -f docker-compose.yml -f docker-compose.prod.yml up -d --build

## Local Vite dev (no Docker, fastest iteration)

Run from the dev clone (WriteMap-Dev/TaibledFork/):

1. Make sure the dev Postgres is running:
     docker compose --project-name writemap-dev -f docker-compose.yml -f docker-compose.dev.yml up -d postgres

2. API — from apps/api/:
     node --env-file=../../.env --watch --import tsx/esm src/index.ts

3. Web — from TaibledFork/:
     pnpm --filter web dev

   Web: http://localhost:4321    API: http://localhost:3000

HMR applies only to the Vite dev server. Changes do NOT hot-reload in Docker
stacks — you must rebuild the container to see them.


## First time / after a fresh clone

Run once per clone to create tables and seed initial data:

  cd apps/api
  DATABASE_URL=$(grep DATABASE_URL ../../.env | cut -d= -f2-) npx prisma migrate deploy
  DATABASE_URL=$(grep DATABASE_URL ../../.env | cut -d= -f2-) npx tsx prisma/seed.ts

Only needed again if you wipe the Docker volume (see below).


## IMPORTANT — do NOT run these unless you mean to wipe the database

  docker compose --project-name writemap-dev down -v   # wipes dev DB
  docker compose --project-name writemap down -v       # wipes prod DB

`down` without `-v` is safe — stops containers but keeps the volume and all data.

Volume names:
  writemap-dev_postgres_data   (dev)
  writemap_postgres_data       (prod)
