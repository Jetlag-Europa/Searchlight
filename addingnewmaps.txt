HOW TO ADD A NEW MAP
====================

1. GET THE CORRECT OSM RELATION ID
   Look up the city on Nominatim to get the right OSM relation ID:
   https://nominatim.openstreetmap.org/search?city=CITYNAME&country=COUNTRY&format=json&limit=3

   Check the "osm_type" (should be "relation") and "osm_id" in the response.
   Also grab the "boundingbox" values — they go in the extent field (order: north, west, south, east).

   Do NOT guess the OSM ID — wrong IDs silently return empty and break the map boundary load.


2. PLACE THE KML FILE
   Copy the .kml file to:
     apps/web/public/<cityname>-hiding-zones.kml

   Naming convention: lowercase, hyphens, no spaces.
   Example: brno-hiding-zones.kml


3. ADD THE GAME TO seed.ts
   File: apps/api/prisma/seed.ts

   a) Add a city feature constant above the GAMES array:

      const CITYNAME_CITY_FEATURE = {
        type: "Feature",
        geometry: {
          type: "Point",
          coordinates: [LAT, LON],        // from Nominatim lat/lon fields
        },
        properties: {
          osm_type: "R",
          osm_id: 123456,                 // from Nominatim osm_id
          extent: [NORTH, WEST, SOUTH, EAST],  // from Nominatim boundingbox
          country: "Country Name",
          osm_key: "place",
          countrycode: "XX",              // ISO 3166-1 alpha-2
          osm_value: "city",
          name: "City Name",
          type: "city",
        },
      };

   b) Add an entry to the GAMES array:

      {
        serverId: "DISCORD_SERVER_ID",    // see SERVERS list at top of seed.ts
        name: "City Name YYYY",
        sentinelValue: "__bundled-cityname-yyyy__",  // must be unique
        kmlPath: "cityname-hiding-zones.kml",
        mapLocationJson: CITYNAME_CITY_FEATURE,
        hidingRadius: 400,               // default radius for all stations
        hidingRadiusUnits: "meters",     // "meters" or "kilometers"
      },

   c) PER-TIER RADIUS OVERRIDES (optional)
      If different station types need different hiding zone sizes, add
      tierRadiusOverrides to the game entry. The keys must exactly match
      the tier values stored in the KML's <Data name="tier"> ExtendedData
      fields. Values are in the same units as hidingRadiusUnits.

      Example — Utrecht 2026 (Train: 400 m, Tram/Bus: 250 m):

        hidingRadius: 250,               // fallback for any station with no override
        hidingRadiusUnits: "meters",
        tierRadiusOverrides: { Train: 400 },

      How it works:
      - When the hiding zones are generated, each station's tier is read
        from its KML <Data name="tier"> field.
      - If that tier has an entry in tierRadiusOverrides, that value is
        used for the circle radius instead of hidingRadius.
      - Stations with no tier, or a tier not in the overrides map, fall
        back to hidingRadius.
      - The radius slider in the UI only affects stations that use the
        fallback hidingRadius — overridden tiers are always fixed.

      KML tier format (Google My Maps ExtendedData):

        <ExtendedData>
          <Data name="tier">
            <value>Train</value>
          </Data>
        </ExtendedData>

      If your KML has no tier data, omit tierRadiusOverrides entirely (or
      set it to null) and all stations will use hidingRadius.

   Server IDs:
     JetLag EU  — 1190673594649415730
     JetLag UK  — 1059625399979606166
     JetLag BNL — 1369664929975767120
     JetLag DE  — 1333139120507064350


4. RUN THE SEED
   The API Docker image does not include tsx (dev dependency), so
   `prisma db seed` does NOT work inside the container. Use raw SQL instead.

   Dev DB (via docker exec):

     docker exec writemap-dev-postgres-1 psql -U taibled -d taibled -c "
     INSERT INTO \"Game\" (id, \"serverId\", name, \"sentinelValue\", \"kmlPath\",
       \"mapLocationJson\", \"hidingRadius\", \"hidingRadiusUnits\", \"updatedAt\",
       \"tierRadiusOverrides\")
     VALUES (
       gen_random_uuid()::text,
       'DISCORD_SERVER_ID',
       'City Name YYYY',
       '__bundled-cityname-yyyy__',
       'cityname-hiding-zones.kml',
       '{...mapLocationJson object as JSON string...}',
       250,
       'meters',
       NOW(),
       '{\"Train\": 400}'   -- or NULL if no tier overrides
     )
     ON CONFLICT (\"sentinelValue\") DO UPDATE
       SET name = EXCLUDED.name, \"updatedAt\" = NOW();
     "

   Live DB: same command but use writemap-postgres-1.

   Note: ON CONFLICT only updates the name. To fix other fields after
   inserting, see step 5.


5. FIXING A FIELD AFTER SEEDING
   If you seeded with wrong values, update directly:

     DATABASE_URL="postgresql://taibled:devpassword@localhost:5433/taibled" \
       node --import tsx/esm -e "
     import { PrismaClient } from '@prisma/client';
     const prisma = new PrismaClient();
     await prisma.game.update({
       where: { sentinelValue: '__bundled-cityname-yyyy__' },
       data: { hidingRadius: 400, hidingRadiusUnits: 'meters' },
     });
     await prisma.\$disconnect();
     "

   Also clear any stale boundary cache if you had a wrong OSM ID:

     await prisma.boundaryCache.deleteMany({ where: { osmId: 'WRONG_ID' } });


6. TEST BEFORE COMMITTING
   Load the map in the browser and confirm:
   - The city boundary loads without error
   - The hiding zones appear correctly
   - The hiding radius looks right on the map
   - If using tierRadiusOverrides: visually confirm that overridden tiers
     have larger/smaller circles than the default, and that moving the
     radius slider does NOT change the overridden circles.

   Then commit and push (dev first, then replicate to live).
